The loop I spend most of my time in with Grove is simple: the agent edits files, I look at what it did. 0.6.1 is about making the second half of that loop less clumsy. Changed files get their own tab, and that tab now updates on its own while the agent is still working — no more switching away and back to see what moved. Around that there's a way to rename workspaces, a move to a single window, and some long-overdue color fixes.

## Changes gets its own tab

The Files space used to be two things behind a toggle: the list of changed files with their diffs, and the full workspace tree with a preview. Two modes in one tab turned out to be harder to find than two tabs, so it's now split:

- **Changes** — changed files on the left, the diff on the right, and the pending-change count on the tab itself.
- **Files** — the whole workspace tree and the preview, including the Markdown preview and PDF export from 0.6.0.

If you'd customized your tab order, the old Files entry turns into both tabs, so neither one disappears on you. Because shortcuts follow visible position, with every tab showing, Files moves from ⌘4 to ⌘5 and Notes from ⌘5 to ⌘6.

A clean working tree — which is most of the time — also looks better now. It used to show two half-empty panes with "No Changes" on one side and "No File Selected" on the other, at different heights with a divider floating between them. Now it's one centered **No Changes** screen, and the split only shows up once there's something to look at.

## Live while the agent works

Until now the Changes list and its badge only refreshed when you switched workspaces, hit Refresh, committed, or changed branches. That's exactly the wrong moment to be stale: while an agent is editing files, the count just sat there.

Now Grove notices when files in the checkout change — edited, created, deleted — and updates the list and the badge on its own. Staging or unstaging from a terminal (a `git add` in the Shell tab, say) counts too. Other workspaces you've visited keep their badges current in the background, and their diffs catch up when you switch back to them.

These refreshes are quiet on purpose. No spinner, no alerts, and nothing redraws if nothing actually changed. That matters if you're halfway through writing a comment on a diff: an unrelated save elsewhere in the repo no longer wipes it out.

One caveat: on network volumes, macOS doesn't always report file changes, so the live updates might not fire there. The Refresh button is still there for that case.

### Paused when you can't see it

An agent writing steadily can produce a lot of file changes, and checking git status every couple of seconds for a window nobody's looking at is wasted battery. So when Grove is hidden, minimized, fully covered by other windows, or on another Space, live refreshes pause. Changes are still noted, and the moment Grove is visible again it catches up with one refresh per workspace, without waiting. Anything already in progress when you switch away just finishes.

## Rename a workspace without renaming the folder

Folder names are often generic or repeated across clones — `app`, `api`, `web` — which makes a long sidebar hard to scan. Right-click a workspace and there's now **Rename…**, which sets a name that only Grove uses. The folder on disk keeps its name, and worktrees are still created under that real folder name, so nothing outside Grove changes.

The new name shows up everywhere Grove shows a workspace: the sidebar, the window title, the Changes and Files headers, the catalog, and the various sheets. **Use Folder Name** in the same sheet clears it, and leaving the name blank does the same. It also works on a workspace whose folder is missing, which is when a recognizable name helps most.

## One window, and closing it doesn't stop anything

Grove used to let you open a second window, and that went worse than it sounds. A second window started its own copy of every agent and shell, removing a workspace only cleaned up one of the copies, and menu commands like the Git ones acted on whichever window you'd touched last.

So Grove now has exactly one main window. File › New Window is gone, ⌘N does nothing, and there are no window tabs. Closing the window no longer stops anything: agents and shells keep running, and clicking Grove in the Dock or choosing **Window › Grove** brings the window back with everything where you left it, output included. While it's closed, menu items that need a checkout are disabled, so they can't act on one you can't see.

## The accent color, everywhere

The accent color you pick in Settings wasn't reaching everything. The spaces rail, the Agent, Shell, and Home sub-tabs, your own bubbles in Chat, and the folder and file icons in the Files tree all stayed system blue no matter which swatch you chose. They follow your pick now.

Also in the sidebar: the badge showing a workspace's unpushed commits used to float over the row, so a long name or path ran underneath it and the badge itself could get clipped. It now has its own space, and long names truncate before reaching it.

## Get it

Grove 0.6.1 is up — [grove.molayab.com](https://grove.molayab.com) for a fresh download, or just wait for the update alert if you're already on 0.6.0.

The split tab and the live refresh look like two separate changes, but they're the same idea. A diff you have to remember to refresh is one you end up reviewing late, after the agent has already moved on. Having the count tick up while it works makes it much easier to step in early.
