Commenting on a diff in Grove used to work one comment at a time: write a note on a line, and Grove jumped you over to the Agent tab with that one comment typed in. Fine for a single nit. For an actual review, six comments meant six trips back and forth, and the agent got your feedback in pieces instead of as one review. 0.6.3 fixes that, and it's the headline. Also in this release: variables in saved prompts and commands, shell tabs that name themselves, terminal links you can actually find, and a few tips for features people tend to miss.

## Diff comments become one review

In the Changes tab, click a line's **+** to comment on it, or shift-click to cover a range. You write the comment right under the diff and stay where you are — ⌘Return adds it, Return is just a newline, Escape cancels. A draft you haven't added yet survives switching to another file.

Added comments collect in a **review panel** beside the diff, grouped by file. It opens with your first comment, and the **Review (N)** button hides or shows it. From the panel you can edit or remove a comment, jump back to its line, or throw the whole batch away (Grove asks first). When you're done, **Send N Comments to Agent** delivers everything as one message. If no agent is available, the same button copies the review to the clipboard instead.

Code keeps changing while you review, especially with an agent working in the same checkout. When a file you commented on changes, each comment follows its line if the code just moved. If the code itself changed, or the file dropped out of the change list, the comment is marked **Outdated** instead of quietly disappearing, so you decide what to do with it.

Two smaller fixes came along with this:

- **Line numbers in comments are right now.** Comments on removed lines, and on context lines in the left column of split view, could point at the wrong line, and split view's right column showed old line numbers on context lines.
- **Quoted code is cleaned before it reaches the agent.** The review quotes the code you commented on, and that code comes from your repository. Grove now strips terminal control characters from it, and from your comments, so a line of code can't end up acting like keystrokes in the agent's terminal.

## Variables in prompts and commands

{% raw %}

0.6.0 added saved prompts and commands. They were plain text, though, so the values you most want in them — the branch, the checkout, a ticket number — still had to be typed every time. Now an entry can include variables in double braces:

| Variable | Becomes |
| --- | --- |
| `{{branch}}` | The branch of the checkout you're in, worktrees included |
| `{{workspace}}` / `{{repo}}` / `{{path}}` | The workspace's name in Grove / its folder name / the checkout's full path |
| `{{date}}` / `{{time}}` | Today's date (`2026-10-20`) / the current time (`14:05`) |
| `{{clipboard}}` | Whatever text is on the clipboard |
| `{{ask}}` / `{{ask:Which ticket?}}` | A question Grove asks you when you run the entry |
| `{{ticket}}`, or any name you like | Also asked for when you run it; a name used twice gets one answer for both |

Named variables can take a default, like `{{env:staging}}`. When anything needs an answer, Grove shows a small form with a live preview of the final text, and cancelling runs nothing. The **?** button in the entry editor lists all of this, so you don't need to come back here to remember it.

I went with `{{…}}` rather than the more obvious `${…}` because `${…}` already means something in the shell. Any command you'd saved with `${HOME}` in it would have suddenly started asking you questions.

Values are made safe before they're typed. Line breaks and control characters are removed, and in commands each value is quoted for the shell, since branch names can legally contain characters like `$`, `;` or `|`. A command that had anything substituted into it is also typed in **without pressing Return**, even if you've set Grove to send entries immediately, so you see the final command before it runs.

## Shell tabs that say what they are

With three shells open, "Shell 2" told you nothing about which one was running the dev server. Shell tabs now name themselves after what's running in them — `vim`, `node`, `python` — and go back to your shell's name (`zsh`) when you're at the prompt. If two tabs run the same thing, they become `node` and `node 2`. A tab you've renamed keeps its name. Hovering a tab shows a close button, which asks first if something is still running in it, the same as **Close** in the context menu.

Two limits worth knowing. The name is the program that's actually running, so `npm run dev` shows up as `node`. And once you rename a tab, there's no way yet to switch it back to the automatic name.

## Terminal links you can find

⌘-clicking a link or a file path in the Agent or Shell pane has always opened it, but nothing told you so — the highlight only appeared once you were already holding ⌘. Now hovering a link shows a pointing-hand cursor and an accent-colored highlight, and after a moment a small **⌘-click to open** hint. A plain click still goes to the program in the terminal, so selecting text and clicking in terminal apps work the same as before.

File paths got two fixes too:

- **Paths open properly.** Clicking a path used to fail with a Finder error. Now a folder opens in Finder and a file opens in its default app. Paths that don't start with `/` or `~` are looked up from the workspace's folder, not from wherever you've `cd`'d to in that shell.
- **Your prompt isn't part of the link.** A prompt like `~/folder on main` used to be picked up as a path to a folder called `folder on`. Grove now only includes spaces in a path when that path really exists on disk, so `~/My Documents` still works.

## Tips for the things people miss

A lot of Grove is easy to miss — the ⌘-click problem above is just one example. 0.6.3 adds small in-app tips for some of the rest: the ⌘K palette, switching spaces with ⌘1…⌘n, clicking a worktree to move the whole window to it, commenting on diff lines, and the Prompts & Commands catalog itself.

Each tip waits until it's relevant — the worktree tip only appears once you have more than one worktree, for example — and goes away for good once you've used the feature. They're spaced out, each one shows at most a few times, and none of them appear over the license screen or an update alert. **Settings → General** has a switch to turn them off and a button to reset them if you want to see them again.

## Open source licenses

Grove is built on open-source work — the terminal emulator, Markdown and diagram rendering, syntax highlighting, and more — and until now the app didn't credit any of it. **Help › Open Source Licenses** now lists every third-party component Grove ships, each with its full license text, read from the app itself so it works offline.

## Get it

Grove 0.6.3 is up — [grove.molayab.com](https://grove.molayab.com) for a fresh download, or accept the update alert if you're already on 0.6.x.

The review panel changes what reviewing an agent's work feels like more than its size suggests. Sending comments one at a time made it a conversation, with the agent reacting to the first note before you'd written the second. Collecting them first and sending them together makes it a review, the same way you'd do it on a pull request, and the agent gets the full picture in one message.
