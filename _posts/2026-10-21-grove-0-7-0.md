Grove went from 0.5.1 to 0.7.0 in five releases, four of them inside two days. If you skipped a few update alerts, or you're still on 0.5.x, that's a lot to piece together from separate notes, so this post covers the whole stretch in one place. 0.7.0 gets the detail, since it's new. The 0.6 releases get a shorter recap, with links to their own posts if you want more.

The thread through all of it is the same: an agent writes code in your checkout, and you review what it did and tell it what to change. 0.6 built most of the tools for that loop. 0.7.0 fixes the parts of it that weren't working yet.

## New in 0.7.0

### The review your agent gets, in the format it prefers

0.6.3 started collecting diff comments into one review that you send to the agent in a single message. That message always had the same fixed layout, and agents don't all want the same thing. Some handle an `@path` mention well. Some do better with `path:42`. And sometimes you want a sentence at the top telling the agent what to do with the review.

{% raw %}

Now you can set the format. **Settings → Catalog → Diff Comments** has three templates:

- **Header** — what goes before the comments, like "Please address this review:".
- **Each comment** — how a single comment is laid out, built from `{{location}}` (where it is), `{{code}}` (the lines you commented on) and `{{comment}}` (what you wrote).
- **Footer** — what goes after the comments.

Next to them are two pickers for how each comment points at its code. **Path** can be the absolute path, the path from the checkout, the file name only, the shortest path that's still unique, or an `@path` mention. **Lines** can be `path:42`, `path#L42`, "path at line 42", or no line numbers at all. A live preview under the editor shows the message you'd actually send, and **Restore Default** puts everything back.

The templates can use the same variables as saved prompts — `{{branch}}`, `{{workspace}}`, `{{date}}` and so on — with one difference: in a review, `{{path}}` is the file you commented on, not the checkout. The editor warns you when you use something a review can't fill in, like `{{clipboard}}` or a question, so you find out while editing instead of when you send. If something can't be resolved at send time — `{{branch}}` while you're not on a branch, for example — Grove tells you and keeps the review, so nothing you wrote is lost.

{% endraw %}

The global format covers every workspace. If one repo needs something different, say because a different agent works on it, right-click the workspace and choose **Diff Comment Format…** to give it its own. **Use default** sends it back to the global one.

Two smaller things came along with this. Sending a review only clears the comments that were actually sent, so one you add or start writing while it goes out stays put. And changing the worktrees folder in Settings could quietly undo changes you'd just made in other Settings tabs. That's fixed too.

### Viewed marks you can trust

The Changes tab lets you mark files as viewed so you can see what's left to look at. In practice those marks went stale. If the agent edited a file after you'd viewed it, the mark usually stayed, because Grove only rechecked the file you had open, and marking a file moved you off it. That's the exact case the marks were supposed to catch.

Three things are different now:

- **Every viewed file is rechecked** whenever the checkout changes, not just the open one. If the agent touches a file you'd already looked at, it goes back to unviewed. This happens in workspaces you've switched away from too.
- **Viewed means opened.** There's nothing to click — once a file's diff has been on screen, it counts as viewed. If it changes while you're looking at it, it goes back to unviewed until you open it again, since you haven't seen the new version yet.
- **Each worktree has its own marks.** Before, viewing a file in one worktree marked the same path as viewed in every other worktree of that repo, even though the diffs were different.

### Acting on several files at once

Since clicking the circle next to a file no longer marks it viewed, it's now a checkbox. Check a few files, or use the usual ⇧-click, ⌘-click and ⌘A, and right-click to act on all of them at once. Checking a file doesn't open it. Clicking a row still opens that file, the same as before.

There are two group actions so far:

- **Mark as Unviewed**, for when you want to look at something again.
- **Discard**, which throws away the changes in every checked file. This can't be undone, so Grove always asks first. The confirmation says how many files will be discarded, and how many of the checked ones it's skipping — renamed and conflicted files can't be discarded this way. If a discard fails partway through, Grove stops there instead of carrying on.

The file list in Changes and Files is also resizable now, and Grove remembers the width you drag it to. So does the height of the Worktrees list in the sidebar.

### Placeholders that stand out

{% raw %}

Saved prompts and commands showed `{{branch}}` in the same plain text as everything around it, so it was easy to miss that an entry had variables at all. Placeholders are now highlighted in the accent color — in the catalog lists, in the ⌘K palette, and in the prompt editor as you type. The single-line command field is the exception: it stays plain while you're editing, because macOS doesn't support styled text in that kind of field. Commands are highlighted everywhere else.

{% endraw %}

### Less chrome, and colors you can read

On macOS 26 the window toolbar is already Liquid Glass, and Grove was drawing a second toolbar under it in every tab, sometimes two. That's gone. Each tab's buttons — New Shell, Restart, Refresh, the Home tab's back and forward — now sit in the window toolbar, and content starts right below it. The Shell tab always shows its sub-tab row now, so you can always see what's running in it.

I also went through the colors. Several accent colors, status colors and badges were too faint to read — the default red accent in dark mode, white text on the yellow accent, the orange count badge. Every accent color, status color and badge now meets the WCAG AA contrast level in both light and dark mode, and there are tests that check it.

A few menus moved around in the process. The **File** menu has **New Project…** (⌘N) and **Add Existing Project…** (⌘O), and the sidebar has a Workspaces header with the same two actions. A new **Workspace** menu has the same actions as the current tab's toolbar buttons, so you can reach them from the keyboard and the menu bar.

## Catching up: 0.6.0 through 0.6.3

If you're coming from 0.5.x, here's the rest of what's new, grouped by what it's for rather than which release it shipped in.

### Saved prompts and commands

- **A catalog per workspace** ([0.6.0]({% post_url 2026-10-19-grove-0-6-0 %})). Save prompts that get typed into the Agent pane and commands that get typed into the Shell pane, from **Prompts & Commands…** in a workspace's right-click menu. Commands run in one reusable **Commands** shell tab, and get a fresh one if something is still running there.
- **A global library**, in Settings → Catalog, for entries that fit more than one repo. A library entry only shows up in the workspaces you assign it to.
- **⌘K** opens a search palette over your catalog, and works while a terminal has focus.
- **Variables** ([0.6.3]({% post_url 2026-10-20-grove-0-6-3 %})). {% raw %}`{{branch}}`, `{{workspace}}`, `{{date}}`, `{{clipboard}}`, `{{ask:Which ticket?}}`{% endraw %} and names of your own, filled in when you run the entry, with a preview first. Values are cleaned before they're typed, and a command with anything filled in is never sent automatically.

### Reviewing what the agent did

- **Changes has its own tab** ([0.6.1]({% post_url 2026-10-20-grove-0-6-1 %})), separate from Files, with the pending-change count on the tab.
- **It updates live.** The list and badge refresh while the agent edits files, without a spinner or losing a comment you're halfway through. Live updates pause while Grove isn't visible, and catch up when you come back.
- **Diff comments become one review** (0.6.3). Comment on lines or ranges, collect the comments in a review panel, and send them to the agent in one message, or copy them if no agent is running. Comments follow their code as it moves, and get marked **Outdated** when it changes.

### Terminals

- **Moving the mouse isn't a click anymore** ([0.6.2]({% post_url 2026-10-20-grove-0-6-2 %})). Moving the pointer over the Agent or Shell pane could act like a click in mouse-aware tools like Claude Code. Fixed.
- **Shell tabs are named after what's running in them** (0.6.3) — `vim`, `node`, `zsh` at the prompt — unless you've renamed them.
- **Terminal links are easier to find.** Hovering a link shows a hint that ⌘-click opens it, file paths open in Finder or their default app, and your prompt no longer ends up as part of a path.

### Workspaces and windows

- **Rename a workspace** (0.6.1) without renaming its folder.
- **One window.** Closing it keeps agents and shells running, and the Dock brings it back with everything where you left it.
- **New Worktree from "&lt;branch&gt;"…** (0.6.0) on the main checkout starts a worktree on a new branch off the one you're on.
- **Missing folders** now get a single "Folder not found" screen and a **Remove from Workspaces** button that works, instead of a pile of alerts.

### Everything else

- **Export Markdown as PDF** (0.6.0), with Mermaid diagrams and highlighted code included.
- **Update alerts that reach you.** Grove checks every few hours and when you come back to it, shows the alert even on the license screen, and remembers when you click **Later**. The About window lists recent release notes.
- **The accent color is used everywhere** (0.6.1), including the tab bars and the Files tree.
- **Tips** (0.6.3) for the features that are easy to miss, which you can turn off in Settings → General.
- **Help › Open Source Licenses** credits every third-party component Grove ships.

## Get it

Grove 0.7.0 is up — [grove.molayab.com](https://grove.molayab.com) or the [direct download](https://github.com/molayab/grove-website/releases/latest/download/Grove.dmg) for a fresh install. If you're already on 0.6.x, accept the update alert. If you're on 0.5.x, the in-app update check gets you there, and from then on updates come to you.

Looking at the whole range at once, it's mostly one feature built in steps: see what the agent changed, comment on it, send the comments back. 0.7.0 fixes the part I didn't trust yet. A viewed mark that stays checked after the file has changed is worse than having no mark, because it tells you you're done when you aren't. Now a checked file means you've seen the version that's there.
