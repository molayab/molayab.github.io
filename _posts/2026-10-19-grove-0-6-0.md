The most repeated thing I do in a Grove session isn't anything clever — it's retyping. The same instructions to the agent, the same dev-server or test command into the shell, once per checkout, over and over. 0.6.0 is mostly about removing that: you can now save prompts and commands, and run any of them from a ⌘K palette. Alongside it there's PDF export for Markdown, a faster way to spin up a worktree, update alerts that you'll actually see, and a fix for workspaces whose folder disappeared out from under Grove.

## Prompts & Commands

Each workspace now has its own catalog of saved entries, and each entry is one of two kinds:

- **Prompts** get typed into the Agent pane — the instructions you'd otherwise paste from a notes file.
- **Commands** are single-line shell commands that get typed into the Shell pane, in whichever checkout you're on.

You edit a workspace's catalog from **Prompts & Commands…** in its right-click menu, and run entries from a new menu in the session toolbar. If the target pane isn't available — say no agent is installed — the entry is copied to the clipboard instead of silently doing nothing.

Commands don't scatter new shell tabs everywhere. The first one opens a tab named **Commands**, and later ones reuse it. Your own shell tabs are never touched. If something is still running in the Commands tab — a dev server, a long test run — the next command gets a fresh Commands tab rather than being typed into that program's input.

### A global library

Some entries make sense everywhere, not just in one repo. Settings has a new **Catalog** tab with a global library for those. A library entry doesn't show up anywhere until you assign it to a workspace, either from Settings or from that workspace's own catalog sheet, so a prompt that only fits three of your repos stays out of the other ten. Unassigning removes it from that workspace only. Deleting it from the library removes it everywhere, and Grove asks before doing that.

The same tab has a **When running an entry** setting. The default, *Fill in only*, types the entry and leaves the Return key to you, so you can read or tweak it first. *Send immediately* presses Return for you. Comments you leave on a diff always only fill in, whatever this is set to — those are usually worth a second look before they go to the agent.

### ⌘K

The menu is fine, but the real entry point is **⌘K**. It opens a search palette over the session: start typing, and it filters your catalog by title and content, with title matches ranked first. Arrow keys move the selection, Return runs it, Escape closes. It works while a terminal has focus, which is where you'll usually be when you want it.

## Export Markdown as PDF

The Markdown preview in the Files space now has **Export as PDF…**, both as a button in the preview header and under the File menu. The export includes everything the preview renders — Mermaid diagrams, highlighted code blocks, relative images. It's always rendered in light mode at a fixed width, so the PDF looks the same whether you're in Dark Mode or have the preview squeezed into a narrow pane. You pick where to save it before anything renders, so cancelling costs nothing.

The PDF is one continuous page instead of being chopped into printer pages. Very long documents do get split, but only at the PDF format's own maximum page size.

## A worktree off the branch you're on

Right-click the main checkout in the Worktrees panel and there's now **New Worktree from "&lt;branch&gt;"…**. It opens the Add Worktree sheet already filled in with a new branch forked from your current one (`my-branch-2`, `-3`, and so on, skipping names that are taken).

It creates a *new* branch rather than reusing the current one because git won't check out the same branch in two places at once. If you try that by hand in the regular sheet, you now get an explanation that points you at this action instead of git's raw error.

## Update alerts that reach you

Until now, Grove checked for updates once at launch and showed the result as a small badge tucked away in Settings → License. Easy to miss. And if your license had expired, you saw nothing at all, which is exactly when an update matters most. The alert's **Later** button also didn't remember that you'd clicked it.

That's all reworked. A new version raises an **Update Available** alert on its own, including while the license screen is showing. Grove checks again every few hours in the background and when your Mac wakes up or you switch back to the app, throttled so it isn't hitting the network constantly. You'll see the alert at most once per version per session, and **Later** now sticks until there's an even newer release.

The About window also has a changelog now, with notes for the last five releases, a badge for the version you have installed, and a download button on the newest.

## Missing folders, and quieter switching

If a workspace's folder was deleted, moved, or on a drive that got unmounted, Grove handled it badly. Every pane raised its own alert at once, and **Remove from Workspaces** could fail, so you couldn't even get rid of the entry. That was caused by a bug in reading saved pinned sites written by an earlier version of Grove, not by the missing folder itself, which is why it hit some setups and not others.

Now a workspace whose folder is gone shows a single **Folder not found** screen with a **Remove from Workspaces** button that works. Removing it only takes the entry off Grove's list — it doesn't touch anything on disk. Grove notices if the folder vanishes while it's open, including a Move to Trash in Finder. Agent and shell sessions are left running in case the drive comes back.

Switching quickly between workspaces that *do* exist also used to raise "The git operation was cancelled" alerts, and could briefly show one workspace's git status on another. Both are fixed.

## Get it

Grove 0.6.0 is up — [grove.molayab.com](https://grove.molayab.com) for a fresh download, or the in-app update check if you're already on 0.5.x. Once you're on 0.6.0, you won't need to go looking — the next update will come to you.

The catalog looks like a small convenience on paper, but it targets the thing a session spends the most keystrokes on. Retyping the same prompt for the fifth time in a day is exactly the kind of friction Grove exists to remove.
